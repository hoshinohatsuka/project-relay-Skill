## 2. 第二思考逐条处置（采纳/降级/拒绝及理由）

**采纳**：八不变量（入 SKILL.md 可审计段）；黑板三文件 + checkpoints（run-manifest/task-ledger/evidence-ledger/checkpoints）；角色表按档位启用；单写者合并、互斥租约、冲突并存不覆盖、半写 artifact 防护；schema_version 拒绝跨版本续跑；P7 对抗复核（含六项自查）；选型理由四级分级；覆盖率分母；固定 commit SHA 与默认分支探测；安全硬化八条（注入防护/submodule/LFS/.env/符号链接/归档）；资源预算表；触发评测扩到 33 例（含 owner/repo、错别字、混合意图、续跑）；claim gate（README 只述已验证能力）；重装备份与哈希比对；先例报告改为可复核查询记录。

**降级**：完整"输出评测 fixture 套件"→ 落为两类本地冒烟（非 LLM 项目 P5 跳过；接手模式含前任错误声明仲裁），其余断言以清单形式写入 templates 与 README 诚实边界，未跑的标 missing evidence。理由：fixture 全套是发布前工程，用户明确"暂不发布、先本地真实测试"。
**降级**：租约/状态迁移的完整状态机 → 简化为"claimed 单租约 + done 需 artifact + blocked/failed 需 reason"，深度档才严格化。理由：主 Agent 单写者模型下，全状态机是过度工程（第二思考自己的对抗表也承认过度编排风险）。
**拒绝**：保留旧名 `oss-teardown-learn`——与用户已确认的改名冲突，用户决定优先。
**拒绝**：脚本做"报告必需章节"校验——章节检查由 P7 对抗复核（模型判断）承担，脚本只做机器可判定的结构校验，避免脆弱的字符串耦合。

## 3. 第一性原理对抗式审查（对 v2.0.0 成品本身）

从"这个技能存在的底层依据"出发逐条攻击：

1. **攻击：双模式是不是伪需求？**——拆解学习和项目接手共享同一理解引擎（P1–P3=H1 盲扫），分开就是两个重复技能；合并后拆解产物可直接喂接手流程。结论：真需求，且合并在第一性原理上更优。
2. **攻击：黑板三文件是不是仪式感？**——快速档单 Agent 时 task-ledger 近乎空转。反制：已按档位裁剪（快速档不开租约），文件仍保留 run-manifest+evidence-ledger，因为"续跑"和"证据可回溯"是八不变量，即使单 Agent 也要落盘。
3. **攻击：真相层级凭什么可信？**——L1"运行结果"最高，但模式A 默认不运行目标代码，L1 在 A 模式几乎不可得。修复：A 模式证据分级（L1 代码证实…L4 推断）与 B 模式仲裁序是**两套**体系，SKILL.md 已分开表述；混淆它们才是真风险。
4. **攻击：五类复述会不会变成模板填空表演？**——若 H1 盲扫偷懒，五类复述就是编的。反制：每类必须带证据或验证方法；H2 对比产生实际差异记录才算数；冒烟测试已验证（前任错误声明被抓住）。
5. **攻击：H5 用户门禁会不会被模型自作主张跳过？**——最危险的单点。反制：SKILL.md 安全边界第 6 条 + H5 加粗 + manifest release_gates 声明；但最终依赖宿主权限系统与用户在场，诚实标注为"流程约束而非技术强制"。
6. **攻击：弱执行者重试会吃掉差价**（生态反方证据）——技能无法控制用户选什么模型。反制：relay-principles 诚实声明 + checkpoint 让失败"便宜且可检测"（这正是路由省钱的前提条件）。
7. **攻击：SKILL.md 11.5KB 是否仍然过载？**——触发只用 description；正文在技能触发后才载入，且细节已下沉 7 个 references。风险可接受，继续观察真实会话的 busywork 信号。
8. **攻击：33 个静态触发用例能证明宿主路由吗？**——不能。静态评测只证明描述与用例的概念匹配；已按诚实原则把"宿主自动触发"记为 missing evidence，待用户本地真实会话测试。
