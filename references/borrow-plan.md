# 借鉴计划（模式D）操作细则

对应 SKILL.md 模式D。**第一性原理**：借鉴 = 独立理解两个项目 → 以「需求→模块」对齐找差异 → 差异映射成「来源 file:line → 用户项目落点」的可审计迁移清单 → 在许可证与版权边界内决定抄还是不抄。它不是 A+B 的拼盘：核心差异在 D2（双项目映射对齐）与 D3（借鉴点双向绑定），以及新增安全维度 D7。

## D0 目标定性（硬门禁，不可跳过）

**先问清、先锚定，再谈别的。** 输入要求是两个目标：用户自己的项目 + 想借鉴的参考项目。

1. 用户只给一个 → 追问第二个；用户指明不清晰（如"这个项目"+"那个项目"）→ **立即停止会话，向用户确认哪个是用户自己的、哪个是借鉴的**。绝不猜。
2. 锚定后登记**双项目登记表**（写入产物头部与 run-manifest）：
   - 用户方：路径、默认分支、**commit SHA**、角色=半成品（走 B 引擎）
   - 参考方：URL/路径、默认分支、**commit SHA**、角色=分析对象（走 A 引擎）
3. 防锚定反转（墨菲 M2）：所有产物文件头强制带登记表；D0 未完成前不启动任何扫描。

## D1 双线独立扫描（顺序不可换，结论互不共享）

- 参考方：复用模式A 的 P1（克隆侦察+SHA）、P2（基线测绘四层）、P3（需求→模块映射）、P4（选型矩阵证据分级+解耦+性能静态审计）。
- 用户方：复用模式B 的 H1（先盲扫后读材料、五类复述）。若用户方有 `.ai/` 交接材料，H1 之后仍按 B 的 H2 处理，但**对比对象是借鉴项目时遵循本模式 D2 的框架**。
- 禁止把一方的结论当作另一方的输入（防锚定与传话失真）。

## D2 对比扫描（本模式核心方法）

**方法**：以「需求→模块」映射表为对齐轴，不是全量文件 diff（两项目语言/结构不同时全量 diff 无意义且成本爆炸）。

| 维度 | 对比项 | 产出 |
|---|---|---|
| 目标与需求 | 两方需求清单 R1…Rn 的覆盖差 | 参考方有而用户方缺的需求（优先借鉴候选） |
| 架构分层 | 入口/业务/数据/外部集成/配置五层结构 | 分层差异 + 值得迁移的分层模式 |
| 编程语言与运行时 | 语言、框架、版本 | 兼容性与迁移成本信号 |
| 模块边界 | 各模块职责与接口（选型证据分级） | 用户方模块的空洞/冗余对照 |
| 选型理由 | 参考方选型的 L1-L4 证据 vs 用户方现状 | 可直接换 vs 需重写的判定 |
| 性能手法 | 参考方 P4 审计出的风险与正资产 | 可借鉴的优化点（标静态风险/假设/benchmark） |

差异表每条：`参考方 file:line ↔ 用户方 file:line`（双端可回溯，绑定各自 SHA）。

## D3 借鉴点提取

借鉴点清单（模板 15）每条字段：**借鉴类型**（架构模式/语言特性/产品设计思路/框架选型/性能手法）、**来源**（参考方 file:line + SHA + 证据等级 L1-L4）、**用户落点**（用户方对应模块/文件，找不到标 `[待定位]`）、**工作量**（S/M/L）、**迁移方式**（直接借鉴/重写借鉴——待 D7 意图询问后定）。

**档位上限**：快速 ≤8 / 标准 ≤20 / 深度按模块分区不限但逐模块列表。上限内按「对用户方价值」排序，宁缺毋滥——借鉴点不是流水账。

## D4 借鉴计划

- 执行顺序纪律沿用模式B H4：**Correctness > Completeness > Maintainability > Performance**。
- **Vertical Slice**：每个借鉴点一条"入口→核心逻辑→出口→测试"完整链路，不按层横切。
- **变更禁区沿用用户方既有禁区**（schema/公共API/认证/已过测试核心模块），借鉴不得绕过禁区。
- 用户方原有 `.ai/` 交接包与 D 计划合并时以 D4 计划的垂直切片为执行骨架，状态写回 PROJECT_STATE。

## D5 社区调研

复用模式A P6 与 community-research.md 的九平台与预算规范。借鉴场景额外查询模板（见 community-research.md 第 5 节）：
- `<参考项目> 借鉴 踩坑` / `<参考项目> 最佳实践`
- `<框架> migration 经验`（若涉及框架迁移）
- `<参考项目> license 争议`（社区对版权/许可证的讨论，仅作线索）

**预算冻结（B7）**：D 的社区查询/Agent 预算耗尽 → 进行中任务标 `blocked` + `reason: "budget_exhausted"` + `retry_after: <ISO 时间>`，checkpoint 记 `blocked_external`，到点自动恢复。不静默降档；"仅理念"部分若预算足够可继续，抄代码部分冻结到预算恢复。

## D6 解耦与性能门（每个借鉴点）

回答"借鉴的代码搬进我的项目会不会引入坏味道"：
- **可 review**：接口边界是否清晰、依赖方向是否单向、可否不启动全应用单测、全局 mutable 状态多少、替换成本。
- **性能静态审计**：阻塞（同步 IO 进事件循环）、N+1、重复计算、缓存缺失、大文件进内存、冷启动重活。输出区分：静态风险 / 可验证假设 / 真实 benchmark（默认不运行目标代码）。

结论写进借鉴点清单（模板 15）的"引入风险"列；风险为中/高的借鉴点自动降权或标注需用户确认后再列入执行。

## D7 安全门（用户门禁，未批准 0 行代码）

**许可证三级判定**（每级都标注"非法律意见，最终由用户拍板"）：

| 级 | 动作 | 处理 |
|---|---|---|
| ① 声明级（L2） | 读两项目 LICENSE/README 中的许可证声明；`python scripts/check_license.py <用户项目> <参考项目>` 给出结构结果（SPDX 提取/矛盾/缺失） | 双方声明清晰且为宽容系 → 前提通过，仍需归因 |
| ② 升级级 | 参考方为 **GPL/AGPL/MPL** 或双方声明**缺失/矛盾**（LICENSE 文件与 README/依赖清单不一致） | **升级用户**：不自动假定；标 missing evidence 并继续 D 计划的"仅理念"部分 |
| ③ 拍板级 | 结合兼容表给出候选判定 | 用户最终决定；被否选项从借鉴点清单移除并记录 |

**常识兼容表**（L4 常识，非法律意见）：
- MIT / BSD-2/3 / Apache-2.0：宽容系，互相可借鉴；Apache-2.0 代码需保留 NOTICE 与专利条款头部；MIT 代码并入 Apache 项目通常可行（保留 MIT 版权与许可声明）。
- GPL-2.0/3.0、AGPL：传染性 copyleft；**抄代码搬入非 GPL 项目 = 冲突**，必须升级用户；仅借鉴设计思路/接口形态不受限。
- MPL/EPL：文件级 copyleft，修改该文件需同许可，其余可闭源——判断权交给用户。
- 无声明：`missing evidence`，问用户；绝不默认"可以借鉴"。
- **归因强制**：无论何种方式，借鉴点清单必须带来源（参考方 SHA+file:line）；产物不得整文件照搬参考方代码而不标注来源。

**意图询问（与许可证并行）**：问清"借鉴代码（复制/移植）"还是"仅借鉴产品设计思维（重写实现）"。**默认安全路径 = 仅理念借鉴**（架构/设计/接口形态，重写实现）；"抄代码"为高风险路径，需用户显式选择且许可证判定通过。

**D7 门禁展示**：双项目登记表、借鉴点清单（含许可证判定记录）、禁区、验收标准、风险与回滚。未获明确批准不动一行代码（同 H5 精神）。

## D8 汇总与交接

产出 `BORROWING_PLAN.md`（模板 14）：
1. 双项目登记表（各自路径+SHA+角色）
2. 差异对比表（D2）
3. 借鉴点清单（D3/D6，含许可证判定记录表）
4. 社区证据（D5，含 missing evidence）
5. 执行顺序（D4，Vertical Slice 化，可接模式B H6 执行）
6. 待用户拍板列表（许可证冲突项、禁区触碰项、抄代码 vs 仅理念的每个借鉴点归类）

交付后**冻结**；用户批准执行 → 借鉴点进入模式B 的 H4/H6 执行单元，checkpoint 记录 `D` 前缀任务 ID。

## 模式D 专属失败模式

| 失败 | 检测 | 恢复 |
|---|---|---|
| 只给一个项目 | D0 双目标缺失 | 停下追问，不猜 |
| 角色锚定反转 | 登记表 + 产物头 | D0 二次确认后才启动引擎 |
| 许可证缺失/矛盾 | check_license.py | 升级用户 + 仅理念借鉴继续 |
| 两项目无共同语言层 | D2 差异表空 | 降级为设计理念借鉴，如实声明 |
| 参考方超大（>500 模块） | 档位降级 + focus | 只深读用户落点相关模块 |
| 用户 D7 后改主意（抄→仅理念） | 门禁后变更 | 回 D3 重出借鉴点清单，不硬推行 |
| check_license.py 输出损坏 | JSON 解析失败 | 手工读 LICENSE 文件，标 missing evidence |
