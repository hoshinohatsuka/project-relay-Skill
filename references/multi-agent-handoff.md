# 多 Agent 跨时段协作协议（黑板模式）

设计原则：多 Agent 的价值是**扩大独立探索宽度**，不是制造重复文本。简单任务不编排——快速档永远单 Agent；只有"可独立拆分且价值足够"时才并行。

## 1. 角色与档位

| 角色 | 职责 | 禁止事项 | 启用档位 |
|---|---|---|---|
| 主协调者（主 Agent） | 建计划、拆任务、分配预算、串行合并、决定补查 | 不代替 Worker 重复干活 | 全部 |
| 基线/模块 Worker | 各管一组互不重叠模块，回传 `file:line` 证据 artifact | 不直接改共享报告 | 标准（≤3）/深度（3–5） |
| 提示词 Worker | 四路扫描+翻译 | 不执行目标代码 | 深度（LLM 项目） |
| 社区 Worker | 按平台调研，记录结构化来源 | 不把搜索摘要当事实 | 标准/深度 |
| 对抗复核者 | 找漏映射、重复计数、无证据结论 | 不直接覆盖原分析 | P7（全部档位，单 Agent 时由主 Agent 自任） |

## 2. 黑板文件（唯一合法的状态交换介质）

```
run-manifest.json     schema_version, skill_version, run_id, 目标(repo/url+commit_sha), 档位, 状态, 预算消耗
task-ledger.json      [{id, title, role, status: pending|claimed|done|blocked|failed, input_scope, output_path, reason?}]
evidence-ledger.jsonl 每行一条：{id, kind: code|community|doc|inference, ref: "path:line"|"url", accessed?, level?, confidence?, disproof?}
checkpoints/          CP-<n>.json {阶段, 校验和, 时间, 下一步}
artifacts/<task-id>/  Worker 隔离产物（临时写这里，校验通过后登记 done）
```

主 Agent 只接收**路径 + 摘要 + 状态**，不接收大段转述——避免传话失真与上下文爆炸。

## 3. 最小完备交接状态

每次跨时段交接（无论换模型还是隔天续跑）必须写出：

1. 分析目标与固定 commit SHA
2. 技能与状态 Schema 版本
3. 已完成 / 进行中 / 阻塞 / 待复核任务
4. 每任务的唯一 ID、负责人、输入范围、输出路径
5. 已检查与未检查范围（覆盖率的分母）
6. 结论、证据、置信度、反证、待确认项
7. 社区查询、来源、日期、失败平台、预算消耗
8. 下一位 Agent 可直接执行的下一步
9. checkpoint 校验结果与是否允许进入下一阶段

## 4. 并发与冲突规则

- **互斥分区**：一个任务同一时间只有一个租约持有者（task-ledger 里 claimed + 负责人）；过期租约可重新领取。
- **单写者合并**：LEARNING_REPORT.md 只由主协调者串行写入，Worker 永不直接编辑共享报告。
- **证据去重**：相同证据按规范化路径或 URL 去重；重复结论并入同一证据条目。
- **冲突并存**：两个 Worker 结论冲突时不裁"最后写入者"，两条都登记进 evidence-ledger（标 disproof 指向对方），交 P7 对抗复核裁决。
- **半写防护**：artifact 无完成标志即视为不完整，忽略并重做该任务。

## 5. 恢复规则（断点续跑）

触发："继续上次未完成的拆解"。步骤：读 run-manifest → 校验 schema_version（不匹配则拒绝自动续跑，给迁移说明）→ 找最近有效 checkpoint → 核对校验和 → 列出 task-ledger 中未完成任务 → 从那里继续。任何阶段失败都从最近 checkpoint 恢复，不从头重跑。

## 6. 资源预算（默认值，可显式调整）

| 项 | 快速 | 标准 | 深度 |
|---|---|---|---|
| 并行 Worker | 1（单 Agent） | ≤3 | 3–5 |
| 社区查询 | ≤4 | ≤12 | ≤24 |
| 单文件读取 | >2000 行先采样 | 同左 | 深读可放宽 |
| 每任务重试 | ≤2 | ≤2 | ≤2 |
| 跳过项 | 二进制/vendor/node_modules/模型权重/数据库转储/压缩包 | 同左 | 同左 |

预算耗尽：显式降档并在 run-manifest 记录，不静默砍内容。

## 7. 并行副本交叉验证（模式B 深度档/用户主动要求）

来自实战的多 Agent 降幻觉模式：不同模型长时间单线工作会**积累幻觉**，且简单的上下文压缩不能消除。做法：

1. 对关键修复/模块，让 N 个 Agent **各领一份独立副本**并行实现（副本间不共享过程，只共享需求与红线）。
2. 完成后**交叉互审**：每个副本由"非作者"Agent 审查，主协调者按证据（测试结果 + file:line）择优合并，冲突处回到真相层级裁决。
3. 成本警告：仅用于"错了很贵"的关键项（认证/计费/数据层）；常规任务用单副本 + 对抗复核即可，否则成本失控。
4. 副本隔离纪律：各副本独立 git 分支或目录，合并前不交叉污染；合并由主协调者单写者执行。

与黑板协议的关系：副本内 Worker 走标准 task/artifact 流；"多副本"只是把同一任务实例化 N 次，属于任务分派层的可选策略，不改变账本结构。
